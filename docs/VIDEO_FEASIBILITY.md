# Video feasibility

## V1 non-NASA review — 2026-10-18

**Incomplete:** no verified low-maintenance, source/collection-approved educational video mode was delivered. The shipping path remains optional NASA per-video review and native hash-verified playback. Manual review is not equivalent to the requested automatic multi-subject video experience.

Bounded research considered Wikimedia Commons' sanctioned MediaWiki discovery and Internet Archive's structured metadata. Commons API access failed from this environment (initial DNS failure, then an escalated TLS reset); it did not produce a verified compatible educational asset. Commons' WebM/Ogg formats need codec/device and attribution validation before the existing narrow MP4 path can be extended. Archive metadata alone did not establish an appropriate small, rights-reviewed, stable educational MP4 collection. Neither repository nor an educational label certifies individual suitability. No collection approval or media-host exception was added, and no YouTube extraction or arbitrary scraping was attempted.

Next video work requires one concrete provider/collection with actual API, asset, rights, suitability and isolated-playback evidence. Retain individual preview/review until that case is established. Do not repeat NASA discovery diagnostics to substitute for this gap.

## Historical YouTube feasibility — 2026-10-17

**Decision: child playback is disabled.** Official `rel=0` still shows same-channel recommendations; channel approval does not approve every topic/video on that channel. Required links, controls, branding, ads and recommendations cannot be hidden, intercepted or covered to claim isolation. No stream extraction, downloads or alternate player. This is an architectural failure of the strict playback requirement, not a tested safety guarantee. [Player parameters](https://developers.google.com/youtube/player_parameters), [Developer policies III.I.4–7](https://developers.google.com/youtube/terms/developer-policies).

## Discovery implemented

`YouTubeClient` defaults to disabled; the app must explicitly pass its disabled-by-default build flag only after setup below. Parent channel-name search retrieves at most five candidates, then verifies IDs through `channels.list`. The parent chooses the actual ID, title and canonical channel URL; similar names are not proof of identity. [Channels API](https://developers.google.com/youtube/v3/docs/channels/list).

Search accepts only parent-approved channels associated by the caller with approved query categories. The callback must authorize the complete query and result title. It defaults to deny. Up to three distinct channels are searched (first three in the supplied list), at most 15 candidates each, one page per channel. There is no infinite feed, automatic next-page request, retry or unrestricted fallback. Requests set video-only, strict SafeSearch, channel ID, embeddable and syndicated filters. A batched `videos.list` rechecks identity, public/processed/embeddable status, non-live status, duration and metadata. Restricted-region videos are conservatively omitted; age-restricted, missing, shorter-than-four-minute and Shorts/Reels-marked results are omitted. Blocked terms scan normalized title, description and tags, including separated lettering. Duration and metadata are heuristics, not age or Shorts certification. [Search API](https://developers.google.com/youtube/v3/docs/search/list), [Video resource](https://developers.google.com/youtube/v3/docs/videos).

API credentials are runtime arguments, never source constants. HTTPS has timeouts, no redirects/cache, bounded response size and typed disabled, credential, quota, network, malformed-response and other errors. Transport can be replaced by local test fixtures only; production defaults to the real official endpoint.

## Setup gates

1. Create a Google Cloud project and enable YouTube Data API v3. Restrict a dedicated key to that API and apply compatible application restrictions; verify those restrictions against the actual Android REST request. Do not embed unrestricted keys in an APK or commit them. Keys in installed apps are extractable. [Google key guidance](https://cloud.google.com/docs/authentication/api-keys-best-practices).
   The Android factory supplies `X-Android-Package` and `X-Android-Cert` using the installed app/signing certificate, as [required for Android-restricted REST keys](https://docs.cloud.google.com/docs/authentication/api-keys#android-apps). This debug package is `family.safe.debug`; use `.\gradlew.bat signingReport` to obtain your build's certificate SHA-1. Enter the key in parent settings; it stays in memory and is cleared on backgrounding. After completing setup/privacy requirements, change the literal `YOUTUBE_API_ENABLED` field in `app/build.gradle.kts` to `true` and rebuild; this enables discovery only, never child playback. Restricted-key acceptance remains untested.
2. Complete Google's child-directed-client notification and applicable privacy requirements before enabling API traffic. Read-only discovery does not remove these duties. No account access, personalization or API write actions are implemented. Publish appropriate privacy disclosures and YouTube attribution if enabling discovery. [Child-directed policy III.J](https://developers.google.com/youtube/terms/developer-policies#j.-child-directed-api-clients).
3. The client stores no result cache. Stored API channel titles/descriptions also count as API data: refresh or delete within 30 days. Parent-authored source preferences should not be presented as current API metadata. [Retention III.E.4](https://developers.google.com/youtube/terms/developer-policies#e.-handling-youtube-data-and-content).
4. Verify actual project quotas in Cloud Console. Official documentation updated 2026-10-15 gives a default separate bucket of **100 search calls/day at one unit each**, plus 10,000 units/day for other endpoints; channels/videos list each cost one. Do not use the older 100-unit-per-search estimate. A populated child search uses up to three search calls and one details call; channel resolution uses one search and one channels call. Fail closed on exhaustion. [Current quota calculator](https://developers.google.com/youtube/v3/determine_quota_cost).

## Isolated playback spike

`app/src/debug/.../PlaybackSpikeActivity.kt` is an unexported, debug-only adult harness. It has no home-screen link and is absent from release. Launch from an explicit in-process debug/instrumentation intent with `videoId` set to an 11-character YouTube ID. It embeds the official player with `rel=0`, user-initiated playback, fullscreen support and no overlays. `loadDataWithBaseURL("https://<installed.application.id>/", ...)` supplies the required app-identity referrer; suppressing that referrer can prevent playback. The base is an identity, not a website allowlist exception. [Official WebView identity guidance](https://developers.google.com/youtube/terms/required-minimum-functionality#api-client-identity-and-credentials).

Adult test sequence: start, pause, fullscreen enter/exit, finish, tap recommendations/title/logo and record resulting destinations and playback errors (including identity errors). This harness deliberately does not filter player internals; keep it away from children. It is not evidence of isolation and must never be enabled as the shipping playback path.

No live key or connected device was provided to this workstream. Live discovery, actual quota, playback/pause/fullscreen/completion/link behavior and device identity were **NOT RUN**. Fixture unit tests exercise the real parser and request construction; they are not live API evidence. The main project test matrix records actual build/test outcomes.
