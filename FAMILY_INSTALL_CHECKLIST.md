# FamilySafe family installation checklist

**Supervised debug pilot only. All physical-tablet checks: NOT RUN (2026-10-18).** An adult must complete these checks on the intended tablet before handing it over. Merging/building the app does not establish independent child-use safety.

1. **Download and verify.** Sign in as the repository owner/collaborator and download `FamilySafe-V1-Supervised-Pilot.apk` from the private draft release linked in the handoff. Compare its SHA-256 with that release's handoff notes. Keep the release draft; do not publish it. Download only the app APK, not the instrumentation APK.
2. **Check compatibility and identity.** Requires Android 8.0/API 26 or newer; package `family.safe.debug`, debug build. Verify the APK signature. Expected signing-certificate SHA-256: `f88398895f95d7a226ff8a38bd96197686fbf6cf2cf88b3acd1f14836b332444`. For an upgrade, compare with the installed app's certificate too. `family.safe` is a separate package and receives no data transfer from this build.
3. **Install without erasing data.** Select the physical serial after checking the tablet's model. Use `adb -s SERIAL install -r FamilySafe-V1-Supervised-Pilot.apk`; require `Success`. Stop on signature/version errors. Never uninstall, clear storage, reset settings or use a downgrade flag to make an upgrade work. See the [exact Windows commands and certificate comparison](docs/PHYSICAL_DEVICE_CHECKLIST.md).
4. **Protect the parent account.** On a new installation, create a private PIN of at least six digits. On an upgrade, use the existing PIN; confirm topics, blocks, requests and review decisions survived. An unexpected setup screen is a failed upgrade check: stop without creating replacement settings. Never record/share the PIN.
5. **Enable approved topics.** Start with a few agreed subjects. Explicitly save approved complete phrases/niches and review any suggested wording. Enabling a subject does not authorize arbitrary extra search words.
6. **Configure blocked content.** Review blocked phrases and add household-specific blocks. Use parent Test rules to verify that blocked phrases override otherwise approved topics. Avoid destructive resets of existing choices.
7. **Review websites.** Consent to and enable only chosen sources and their topic associations. Vikidia/Wikijunior are community edited, not suitability certified. Keep National Geographic Kids disabled. Generic directory approval can expose multiple pages within its allowed scope.
8. **Test allowed and denied searches.** Try an approved complete phrase, an unknown extension and a blocked/social phrase. Denied searches must show no launchable results; requests must not unlock settings or approve themselves. Do not count empty/error results as working search.
9. **Read an article.** Open a real educational result; check readable text, scrolling, source/revision/license attribution and Back. Other articles, edit/login pages, external links and external apps must stay blocked. Images and interactive content are intentionally unavailable.
10. **Review videos individually.** For the one non-NASA lesson, enable a topic and explicitly save `addition`; in Videos, select that topic and consent to Khan Academy via Internet Archive, then Find vetted lesson. Only Addition 3 is available. Watch the entire approximately nine-minute lesson and review credits/license before deliberately approving it. Source consent/discovery is not approval; the app does not enforce watching to completion. Pending/rejected items must remain hidden. Existing NASA items also need individual review. No automatic collections, YouTube or social feeds.
11. **Exercise playback.** For an adult-approved item, check visible playback, sound, pause/resume, seek and Close/Back. Confirm no next-video feed or external player opens. Disable the source/topic or reject the trial item and verify access is revoked. Additions to the vetted catalog require separate engineering verification.
12. **Check rotation and lifecycle.** In both portrait and landscape, check home, search, PIN, parent settings, article and video controls. Back from settings and Home/app-switch/background must lock parent access. Backgrounding must stop playback and clear the selection/preview state. Foreground Close from a parent preview may return to the authorized review screen.
13. **Review Android/Family Link protections.** The adult verifies the tablet's actual parental supervision, app-install approval, device settings and account controls. FamilySafe does not configure or prove these protections. Manage any temporary installation/USB debugging access afterward.
14. **Check alternate routes.** Review other browsers, YouTube/social apps, guest/account switching and system apps with the adult. Restrict alternatives using the tablet's available controls and test the resulting behavior. FamilySafe alone is not a device lock or universal filter.
15. **Test network recovery.** At a convenient time, the adult disconnects/reconnects the test network. Search and interrupted video downloads must fail closed and allow a deliberate retry without partial playback or external fallback. A fully downloaded local video may continue offline. Record failures rather than loosening restrictions.
16. **Restart and recheck.** Relaunch and, when convenient, reboot manually. Parent access must start locked; existing PIN, retry delays, topics/sources/blocks, requests and video decisions must persist. Confirm child-only access to the intended reviewed material. Stop the trial if a required check fails.

**Never run resetting instrumentation or `disposableInstrumentation=true` on a family tablet.** No test fixture approval substitutes for adult content/rights review. Record PASS/FAIL/NOT RUN privately using the [detailed physical checklist](docs/PHYSICAL_DEVICE_CHECKLIST.md); do not upload family settings, PINs or private device logs.

Known limits: one mathematics lesson in the non-NASA catalog; narrow web results; community content can change; content filtering is not semantic moderation. An earlier live video transfer failed before a successful retry, with cause unresolved. Physical performance, codec behavior and household restrictions remain unverified until the checks above are completed.
